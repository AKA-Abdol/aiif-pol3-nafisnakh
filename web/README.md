# فرانت‌اند نفیس نخ

رابط کاربری کوپایلوت فروش. React 19 + TypeScript + Vite، راست‌چین، بر پایهٔ `docs/API.md`.

## اجرا

<div dir="ltr">

```bash
# ۱. بک‌اند (از ریشهٔ پروژه)
.venv/bin/uvicorn nafisnakh.api:app --port 8000

# ۲. فرانت
cd web
npm install
npm run dev        # http://localhost:5173
```

</div>

`npm run build` برای بیلد پروداکشن · `npm run typecheck` برای بررسی نوع‌ها.

> **CORS لازم نیست.** بک‌اند میان‌افزار CORS ندارد، پس `vite.config.ts` هر چیزی زیر `/api`
> را به `127.0.0.1:8000` پروکسی می‌کند و پیشوند را برمی‌دارد. بک‌اند دست‌نخورده می‌ماند.
>
> **چرا `/api`؟** قبلاً نام خودِ مسیرها پروکسی می‌شد (`/customers`، `/report`، …) و این با
> مسیرهای خودِ برنامه تصادم داشت: Vite پروکسی را پیش از history fallback اجرا می‌کند، پس
> reload روی `/customers/C_117580` به‌جای برنامه JSON خام برمی‌گرداند. پیشوندی که هیچ صفحه‌ای
> از آن استفاده نمی‌کند این تصادم را ندارد. در پروداکشن یا بک‌اند را زیر `/api` سوار کنید یا
> `VITE_API_BASE` را به آدرسش بدهید.

## صفحه‌ها

| مسیر | کار | فراخوان‌ها |
|---|---|---|
| `/` | صف امروز، با فیلتر سطل و اولویت | `/summary` (رایگان) · `/actions` (**پولی، فقط با کلیک**) · `/feedback` |
| `/customers` | جدول دفتر با فیلتر و مرتب‌سازی سمت کلاینت | `/customers?limit=1000` |
| `/customers/:id` | پروندهٔ ۳۶۰ — قلب برنامه | `/customers/:id` · `/customers/:id/tools` (تنبل) |
| `/customers/:id/meeting` | آماده‌سازی جلسه، دو مرحلهٔ صریح | `meeting/plan` (رایگان) → `POST meeting` (**پولی**) |
| `/system` | سلامت سیستم | `/calibration` · `/feedback` · `/tools` · `/agents` |

## قواعدی که در کد رعایت شده‌اند

هفت مورد «نباید»ِ `docs/API.md` §741 مستقیماً در ساختار پیاده شده‌اند:

1. **هیچ مسیر پولی خودکار صدا زده نمی‌شود.** `refetchOnWindowFocus` و `refetchOnReconnect`
   سراسری خاموش‌اند و `/actions` با `enabled: armed` پشت دکمه است. refresh مرورگر هزینه
   نمی‌سازد.
2. **هر شناسهٔ شاهد کلیک‌پذیر است.** `EvidenceChip` → `EvidenceDrawer` سراسری →
   `/evidence/:id/rows` با جدول پویا از روی `columns` و خروجی CSV.
3. **هیچ عددی از `payload` داخل جملهٔ فرانت نمی‌رود.** `payload` فقط به کاشی و نمودار
   می‌رسد؛ جمله‌ها همیشه از `claims` می‌آیند.
4. **تحلیل‌گرهای بیدارنشده حذف نمی‌شوند** — زیر یک `details` با `reason_fa` خودشان.
5. **قیدها یک بار بالای دستور جلسه** می‌آیند، نه در هر کارت.
6. **ستون‌های drill-down hardcode نشده‌اند** — از `columns` پاسخ ساخته می‌شوند.
7. **`source: "rules"` پنهان نمی‌شود** — نشان «متن قالبی — مدل در دسترس نبود» می‌گیرد.
   همین برای `synthesis_source` در پنل رابطه هم اعمال می‌شود.

## چیزهایی که صریحاً درست شده‌اند

| مورد | قبل | حالا |
|---|---|---|
| reload روی `/customers/:id` | JSON خام (پروکسی مسیر را می‌بلعید) | برنامه بالا می‌آید |
| برگشت به صفحهٔ صف | دکمهٔ پولی دوباره | همان صف، از کش، رایگان |
| برگشت به صفحهٔ جلسه | دستور جلسه گم می‌شد | از کش همان نشست |
| `as_of` بعد از reload | به پیش‌فرض برمی‌گشت | در URL می‌ماند |
| پنل رابطه | فقط `summary_fa` | هر نُه فیلد، با لحن و تعهدهای معطل |
| خطای رندر | صفحهٔ سفید | Boundary با پیام و دکمهٔ تلاش دوباره |
| چاپ | کل برنامه با nav و دکمه‌ها | فقط محتوا، با `details`های بازشده |

## نکته‌های پیاده‌سازی

**تاریخ مبنا در URL است.** در query string نگه داشته می‌شود (`?as_of=…`) و به هر درخواست
اضافه می‌گردد، تا یک لینک اشتراکی همان اعدادی را نشان دهد که فرستنده دیده بود. تغییرش کل
ایندکس شواهد را باطل می‌کند، چون ادعاهای قبلی نسبت به لنگر قدیمی حساب شده بودند. هر
`<Link>` داخلی از `useLink()` رد می‌شود تا لنگر را با خود ببرد.

**ایندکس شواهد.** پاسخ `/customers/:id` همهٔ شواهد را با خودش می‌آورد؛ اینها در یک
`Map<id, Evidence>` می‌نشینند تا chip بدون رفت‌وبرگشت شبکه، متن ادعا را در tooltip نشان دهد
و drawer بلافاصله عنوان و فرمول را داشته باشد.

**بازخورد.** `detectors` همیشه از `action.signals` همان کارتی که کاربر رویش کلیک کرده
فرستاده می‌شود — وگرنه سرور `400` می‌دهد. پس از ثبت، کش `/actions` فقط **کهنه** علامت
می‌خورد (`refetchType: "none"`)، نه پاک: پاک‌کردنش فهرستی را که کاربر هنوز رویش کار می‌کند
خالی می‌کرد و گرفتن دوباره‌اش دوباره پول خرج می‌کرد. ساخت مجدد پشت «تنظیم صف» می‌ماند.

**هیچ نتیجهٔ پولی با جابه‌جایی از بین نمی‌رود.** صف با کلید
`as_of + limit + bucket + priority` و دستور جلسه با کلید `as_of + id + agents` در کش
TanStack می‌نشینند. برگشتن به صفحه، همان نتیجه را رایگان نشان می‌دهد؛ ساخت دوباره فقط با
کلیک صریح («اجرای دوباره» / «ساخت صف») ممکن است و پیش از آن `CostNotice` می‌آید.

**جمع‌بندی رابطه.** `GET /customers/:id` روی مرحلهٔ `quadrant` اجرا می‌شود و گرهٔ رابطه
*بعد* از آن می‌آید، پس این جدول در حالت عادی خالی است. `nafisnakh/api.py` حالا اگر یک اجرای
`full` از قبل در کش سرور باشد، رابطه را از همان‌جا برمی‌دارد — هرگز اجرای تازه‌ای شروع
نمی‌کند. یعنی پنل رابطه پس از ساخت صف پر می‌شود و پیش از آن صادقانه می‌گوید چرا خالی است.

**زمان انتظار.** پروکسی Vite تایم‌اوت ۱۰ دقیقه‌ای دارد چون اجرای سرد `/actions` طولانی است.
صفحهٔ جلسه به‌جای spinner، تخمین ~۱۲ ثانیه به ازای هر تحلیل‌گر نشان می‌دهد.
